## Finding

**COV-1, P2, high confidence: dark refusal tests do not prove preservation of previously learned knowledge.** `tests/freehold_crafted_availability.test.ts:93` builds each carried-pattern refusal with no sentinel learned recipe; `:103` only checks the attempted recipe remains unknown. The actual dark-host path reaches rollback in `src/sim/professions/pattern_items.ts:156`. Replacing `meta.knownRecipes = previousKnowledge` with `meta.knownRecipes = new Set()` would destroy unrelated learned recipes while satisfying these assertions. The tooltip-versus-use cases at `tests/recipe_pattern_tooltip_view.test.ts:514` have the same empty-knowledge setup. This matters because the acceptance claim is preservation of knowledge, copies and fees on acquisition refusal, not merely failure to learn the attempted recipe.

The same preservation claim is only partial in the dark quartermaster cases, `tests/freehold_crafted_availability.test.ts:109`: they verify Marks and requested-item counts, but do not snapshot pre-existing knowledge, copper or other inventory. A useful repair is to seed an ordinary known recipe, nonzero copper and an unrelated inventory sentinel; compare the complete relevant state after each refused operation. Keep the ordinary vendor success control. Exercise all three manuals, and preserve the existing per-recipe dark training/crafting checks. Count these omissions as one preservation coverage finding.
